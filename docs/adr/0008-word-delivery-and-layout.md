# ADR-0008: Word 交付双形态与草稿/成品目录分层

- 状态: Accepted (2026-08-13)
- 取代/关联: ADR-0005(转换/交付纯文档能力 — 本 ADR 修订其交付形态与目录约定);ADR-0004(self-service 包定位)
- 起因: 用户反馈「每次生成一个 md 就生成一个 docx,不符合标准;docx 应只有一份(技术交底书)」。grilling 裁决:**交付形态 = 两者都出**(三件套分文件 docx + 合并技术交底书.docx);**目录 = 草稿/附图/成品 三层**。

## 背景

ADR-0005 定 Stage-5 Word 交付为 `说明书.md / 权利要求书.md / 摘要.md` 各出同名 .docx(共 3 份),面向发明人自助直接向 CNIPA 电子申请分文件上传。实际使用暴露两点问题:

1. **交付物语义混杂**:3 份分文件 docx(递交用)之外没有供「交代理机构 / 内部评审」的单一文档;且「每个 md 都转 docx」的表述让成品与草稿混在 `patent-application/` 同一层,看不出哪些是可直接使用的成品。
2. **附图管线平铺**:`figN.svg` + `figN.png` 与 md 草稿同目录,无法区分可再生成源 / 预览 / 嵌入位图。

## 决策

### 1. Word 交付 = 双形态(both)

Stage-5 组装后产出**两个交付集**(发明 / 实用新型):

- **申请文件**(CNIPA 分文件递交用):`草稿/权利要求书.md / 说明书.md / 摘要.md` → `成品/申请文件/` 同名 .docx(固定文件名、分文件对应、无时间戳)。
- **技术交底书**(交代理机构 / 内部评审用):先按 `patent-application/references/disclosure-document.md` 组装 `草稿/技术交底书.md`(合并申请信息 + 说明书 + 附图 + 权利要求 + 摘要),再转 `成品/技术交底书.docx`。**一份交底书 = 一个 docx**。

降级链(python-docx 内联 → pandoc → 交付 .md + 手动另存)与 fail loud 不变(ADR-0005);转换命令从 `草稿/` 目录执行,附图引用 `../附图/嵌入/figN.png`。

### 2. 目录分层:草稿 / 附图 / 成品(三层,不混)

`patent-application/` 根下三个文件夹:

- `草稿/`:可编辑 md(申请信息 / 权利要求书 / 说明书 / 摘要 / 附图说明 / 技术交底书组装稿)。
- `附图/源文件|预览|嵌入/`:dot 源(可再生成)/ svg 预览 / png 嵌入位图。
- `成品/申请文件/` + `成品/技术交底书.docx`:直接可用交付物,Stage-5 生成。

**原则:草稿与交付物永不混层**;`成品/` 下的一切都是可直接使用的成品,`草稿/` 下的一切都不是。

### 3. 附图三子层

`源文件/`(.dot,可再生成)、`预览/`(.svg,预览 / 版本留存)、`嵌入/`(.png,Word 内联嵌入与递交位图)。md 草稿中的图引用写为相对路径 `../附图/嵌入/figN.png`。

## 后果

- patent-application(Stage 1/2/3/5)、patent-drawings(Step 2/4 + 完成标准)、patent-compliance(输入)、patent-filing(文件清单)、conversion(交付表 / 降级链 / 组装步骤)路径与交付形态同步更新;新增 `patent-application/references/disclosure-document.md`(交底书结构单一来源)。
- 外观设计分支:仅 md 移入 `草稿/`,`图片/` 即递交交付物;不引入 docx 交付。
- 无新增依赖、无脚本(仍为零脚本纯文档能力,ADR-0005)。
