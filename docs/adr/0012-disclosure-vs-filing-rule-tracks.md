# ADR-0012: 撰写规则双轨——交底轨与申请文件轨分离

- 状态:Accepted (2026-08-13)
- 关联:ADR-0008(工作区与交付)、ADR-0009(自助链路五技能)

## 背景

技术交底书的组装表原先以申请文件草稿（说明书.md / 权利要求书.md / 摘要.md / 附图说明.md）为章节来源，而「仅交底书」路由并不派发 patent-drafting，这些产物并不存在。代理人为凑来源要么先跑一遍申请文件链——把法定门（五部分结构、权利要求格式/引用/清楚性、支撑链、上位化三问）整套压到一份面向代理机构的非法定文件上；要么对着缺失来源凭空补写。交底书是给人类读者（代理机构 / 内部评审）的文档，专利法在代理机构撰写申请文件时才进场，申请文件的规则本就不该约束它。

## 决策

1. **规则双轨（disclosure track / filing track）**，单一定义在 `skills/self-service/patent-intake/references/disclosure-document.md`：
   - **交底轨**只约束 `技术交底书.md/.docx`，完整规则集 = 该文件的组装表 + 组装规则 + 诚实红线；
   - **申请文件轨**只约束权利要求书 / 说明书 / 摘要（patent-drafting 的法定门）。
   - 轨间互不进口：交底轨明文「不写在本文件里的规则不是交底书要求」，冲突时交底轨规则在交底书上赢。
2. **组装表路由感知**：每章节给双来源列——两者路由用申请文件草稿，仅交底书路由用四要素记录 + 已确认材料；绝不为凑章节运行 patent-drafting。附录 A（权利要求草案）/ 附录 B（摘要）条件化：草稿存在才收录，否则整项省略。
3. **诚实红线为双轨共享**的唯一硬约束；图的重绘/图类型路由纪律是申请文件轨要求，交底轨可原样内嵌已确认图。
4. 联动：patent-intake 路由表与派发一节写明 disclosure track 不派发撰写/附图/自检三个 discipline；conversion Step 0 按路由取来源，仅交底书路由只转换 `技术交底书.md` 一件。

## 后果

- 「仅交底书」交付不再触发任何法定门：无五部分强制、无权利要求句式重写、无支撑链阻断、无法定开头句式。
- patent-drafting 的完成标准语义不变，但适用范围显式收窄到申请文件轨。
- CONTEXT.md 词表新增「规则双轨」，后续技能引用双轨词汇时以 disclosure-document.md 为单一事实源。
