# 权利要求书撰写

输入:四要素(技术问题/技术方案/区别特征/技术效果)+ 申请类型(发明/实用新型)。缺输入先回去问,不凭猜测写。

## 类型差异(先定模板)

| 维度 | 发明 | 实用新型 |
|---|---|---|
| 独权客体 | 产品/方法/系统 | **只写产品**(形状/构造/结合,专利法第2条) |
| 方法特征 | 可写算法/流程 | **不写方法步骤**作主要特征;只允许已知方法名称作限定 |
| 附图标记 | 可引用,须括号 | 同左 |
| 实务条数 | 8-15 | 5-10 |

## 五步撰写,每步有完成标准

### 步骤1 圈定必要特征 → 完成标准:每个保留特征都通过删除测试

对方案里的每个特征问:**删掉它,技术问题还解决吗?** 能 → 非必要,下沉到从权或删掉。独权只留"删了就解决不了问题"的特征。

- 必要特征来自**问题**,不来自实现细节:解决"识别不准"问题,必要的是"识别机制",不是"摄像头装在左上角"。
- 效果是区分还是增强:只带来效果提升、不影响问题解决的特征,不是必要特征。

### 步骤2 写独权 → 完成标准:一段式、前序+特征两部分、一个句号

格式(细则第24条):

```
一种<上位主题名称>,包括:<与最接近现有技术共有的必要特征>;其特征在于:<区别于现有技术的特征>。
```

- 前序部分:主题名称 + 共有特征。"一种<X>"的 X 用**上位词**(见步骤3),不用产品名。
- 特征部分:"其特征在于"引出区别特征。区别特征没想清楚,回阶段1补问,不要硬写。
- 一项申请只有一个独权(细则第24条),写在所有从权之前。

### 步骤3 上位化阶梯 → 完成标准:每个词都过了三问

沿"问题的本质"把具体实现逐级抽象,从窄到宽排:

```
层1 具体实现  手机APP通过蓝牙连接手环,读取心率
层2 中间概括  客户端与可穿戴设备通信,获取生理数据
层3 功能概括  第一终端与第二终端通信,获取用户状态数据
```

**三问判据**(每上一层都要过):
1. 概括后**还解决原技术问题**吗?→ 不过,回退一层。
2. **说明书有实施例支撑**吗?(专利法第26条第4款:权利要求以说明书为依据)→ 不过,要么补实施例,要么回退。
3. 是**纯功能限定**吗?(只说了"能干什么",没说"怎么实现")→ 是,必须至少公开一条实现路径,否则不支持/不清楚。

- 上位词方向由问题本质决定:问题在"用户与数据服务的交互",APP→客户端 成立;问题在"蓝牙低功耗省电",APP→客户端 不成立,该限定要保留。
- 独权用层2-3,层1的实现细节全部下沉到从权。

### 步骤4 从权退路布防 → 完成标准:每个实施例都有对应退路,引用规则无违规

从权 = **退路**:独权太宽被驳时,从权顶上。布防三个方向,按商业重要度排序:

| 方向 | 手法 | 例 |
|---|---|---|
| 细化 | 把实现细节收进从权 | 独权"处理单元"→ 从权"所述处理单元包括特征提取模块和匹配模块" |
| 变体 | 替代实现各占一条 | 独权"第一通信方式"→ 从权"所述第一通信方式为蓝牙"+"为Wi-Fi" |
| 增强 | 附加功能特征 | 独权方案 + 从权"还包括:根据用户反馈更新所述匹配模型" |

引用规则(细则第25条):
- 从权只能引用**在前的**权利要求。
- 多项从权只能择一引用:"根据权利要求1或2所述的…"。
- 多项从权**不得**作为另一项多项从权的基础("根据权利要求3或4所述的…"若3是多项就违规)。
- 引用部分写全主题:"根据权利要求1所述的一种<主题>…"。

### 步骤5 清楚性收敛 → 完成标准:逐条过下表,零命中

| 检查 | 规则 |
|---|---|
| 术语与说明书一致 | 细则第22条;权利要求先写"传感器",说明书就别写"感应器" |
| 主题名称一致 | 独权、从权引用、说明书名称三处一致 |
| "所述"有先行词 | "所述处理器"前必须出现过"处理器"或"一种处理器" |
| 无"如图所示" | 细则第22条:除绝对必要外不得用"如图…所示" |
| 附图标记仅括号 | 细则第22条:标记放括号内,不作限定 |
| 无引导词 | "优选""例如""最好"是撰写用语,不进权利要求 |
| 无商业宣传语 | 细则第20条(说明书)/第22条 |
| 一项一句号 | 实务惯例:每项权利要求以一个句号结束 |

## 语言转换表(产品词 → 专利词)

| 发明人说的 | 权利要求写 |
|---|---|
| 手机/平板 | 移动终端、便携式计算设备 |
| 服务器/云端 | 服务端、远程处理单元 |
| 按钮/页面/弹窗 | 输入控件、显示界面、提示信息 |
| 微信/支付宝/App | 应用程序、第三方应用接口 |
| 摄像头 | 图像采集装置 |
| 芯片/CPU | 处理单元 |
| "自动" | 根据…确定/响应于…(写明触发条件) |
| 口语连接词 | 响应于/根据/基于/配置为 |

## 常见错误(对/错对照)

| 错误 | 问题 | 修正 |
|---|---|---|
| "一种智能门锁,其特征在于:能够自动识别用户" | 纯功能限定,无实现路径 | 写明识别机制:"包括图像采集模块和与所述图像采集模块连接的识别模块,所述识别模块配置为…" |
| 把"摄像头装在左上角"写进独权 | 实现细节锁死保护范围 | 下沉从权:"所述图像采集模块设于门体的上部" |
| "一种X的方法"与"一种X"装置权混写 | 主题混用,审查必驳 | 方法权写步骤,装置权写结构,分开 |
| 多项从权引用多项 | 违规(细则第25条) | 改成引用单项,或拆开 |
| 独权里写"优选地,摄像头为红外摄像头" | 引导词,限缩混乱 | 删"优选地",该限定进从权 |

## 完成标准(交稿前)

- [ ] 独权过了步骤1删除测试,不是实现细节堆砌
- [ ] 步骤3三问全过:概括不丢问题、说明书有支撑、无纯功能限定
- [ ] 每个实施例/变体在从权里有退路
- [ ] 步骤5清单零命中
- [ ] 无编造的现有技术、无虚构数据
