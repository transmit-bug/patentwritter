# 递交前自检

输入:权利要求书.md + 说明书.md + 摘要.md + 附图说明.md(+ 补正阶段时的原申请文件)。输出:检查报告(严重级别 + 位置 + 修复指引)。

## 检查项,每项给了"怎么查"

### 1 支撑链(权利要求 ↔ 说明书)→ 逐条特征找出处

怎么查:把每条权利要求拆成特征;每个特征去说明书找落点(发明内容方案段或实施例)。找不到 = critical(专利法第26条第4款:权利要求以说明书为依据)。
- 独权上位词:说明书必须有至少一个具体实施例落下去。
- 从权附加特征:必须能在实施例对上。

### 2 清楚性 → 机械扫描

怎么查:全文搜索下列模式——
- "所述 X",向前找 X 的首次引入("一种X"/"X");找不到 = 引用基础错误。
- "优选""例如""最好""可选的" 出现在权利要求 = 引导词残留。
- "如图…所示""如说明书…所述" 出现在权利要求 = 违规(细则第22条)。
- 主题名称不一致:独权主题 vs 从权引用部分 vs 说明书名称。

### 3 主题一致性 → 三处对表

怎么查:建表——请求书名称(申请信息.md)、独权主题名称、说明书名称。三处不一致 = critical(细则第20条:名称与请求书一致)。

### 4 附图标记一致性 → 双向核对

怎么查:说明书文字提取标记集 A;附图/附图说明提取标记集 B。A−B(文字有图无)和 B−A(图有文字无)都应为空(细则第21条)。同一部件两种编号 = critical。

### 5 实用新型形式 → 三条硬规则

怎么查(实用新型才跑):
- 独权是产品权(有"装置/设备/系统"类主题),不含方法步骤为主的特征 → 违反 = critical(专利法第2条第3款)。
- 有结构图(细则第20条)。
- 附图标记一致性同上。

### 6 摘要合规 → 一条条读

怎么查:摘要是否含名称、技术领域、问题、方案要点、主要用途(细则第26条);是否有商业宣传语;附图摘要是否已指定。

### 7 修改超范围(仅补正阶段)→ 对照原文件

怎么查:把修改稿和原申请文件逐特征 diff。新增的、原文件没有记载的特征 = 超范围(critical,专利法第33条)。"删除"不超范围,"改特征"要谨慎——改了就超,除非原文件有依据。

## 报告格式

```markdown
# 检查报告
| 级别 | 位置 | 问题 | 修复指引 |
|------|------|------|----------|
| critical | 权利要求1 特征"识别模块" | 说明书无"识别模块"出处 | 在实施例补写识别模块结构 |
| important | … | … | … |

## 修复建议(按级别排序)
```

级别定义:
- **critical**:不修,递交必出问题(驳回/补正/超范围)。
- **important**:大概率被审查员指出,应修。
- **minor**:质量提升,可选。

## 完成标准

- [ ] 7 项检查全部执行(实用新型 5 项必跑,发明跳过实用新型专用项)
- [ ] 报告含级别、位置、修复指引
- [ ] critical 全部给出一句话修复方案
