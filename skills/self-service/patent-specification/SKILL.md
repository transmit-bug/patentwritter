# 说明书撰写(五段式)

输入:四要素 + 权利要求书(先写权利要求,再写说明书——说明书是权利要求的支撑体)。五段式结构是法定要求(细则第20条),每段有标题。

## 段1 技术领域 → 完成标准:一句"本发明涉及…技术领域,特别涉及…"

写法:先大类后小类。"本发明涉及<大领域>,特别涉及<小领域>"。小领域要落到权利要求主题上,与独权主题名称呼应。

## 段2 背景技术 → 完成标准:只有三类素材,无虚构文献

**诚实红线**(本技能最硬的一条):背景技术只写三类素材——

1. **发明人已知的现有方案**:如实描述(结构/做法/缺陷),有专利号或文献就写,没有就不写编号。
2. **客观通用问题**:不指向具体文献,描述该领域公认的问题状态("现有技术中,<问题>是普遍存在的…")。
3. **检索工具真实返回的结果**:引用真实公开号。

禁止:编造专利号/文献/公司名/"某公司公开了…"。**判断:这处内容用户说得出出处吗?说不出就去掉或改成通用问题表述。**

结构:现有方案是什么 → 存在什么问题(客观、具体)→ 该问题带来的后果 → "因此,亟需一种<方案>…"收尾引出发明内容。

## 段3 发明内容 → 完成标准:问题/方案/效果三呼应,方案段覆盖全部权利要求

三呼应(细则第20条:对照现有技术写明):
- **要解决的技术问题**:与背景技术的缺陷一一对应;一句话,可加一句"本发明目的在于…"。
- **技术方案**:把独权内容展开成段落(与独权逐特征对应),再"进一步地…可选地…"概述从权。**每条权利要求的特征都要在方案段或实施例段有出处**(支撑链,专利法第26条第4款)。
- **有益效果**:对照现有技术写。**有数据写数据(写明测量条件),没数据写机理推理("由于…,因此…")**。禁止编造实验数据。

## 段4 附图说明 → 完成标准:每图一句,标记不越界

"图1为本发明实施例提供的<X>的结构示意图;"每图一句,全部图都列。图号与附图一一对应(细则第21条)。

## 段5 具体实施方式 → 完成标准:本领域技术人员照此能实现

**公开充分**的判据(专利法第26条第3款):一个本领域普通技术人员读完能做出这个东西。缺参数、缺步骤、缺数据流都是不合格。

实施例写作协议,每个实施例都要覆盖:
1. **结构/连接**:部件清单 + 连接关系(对照附图标记写)。
2. **工作流程**:从输入到输出的完整过程,关键步骤写明。
3. **关键参数**:数值/阈值/次数/尺寸,给出范围或具体值。
4. **数据流**:数据/信号在模块间怎么流动、谁触发谁。

支撑链要求:
- 权利要求里每个上位概念,至少有一个具体实施例落下去(指南 第二部分第二章)。
- 从权的每个附加特征,实施例里要能对上。
- 至少2-3个实施例,且**必须是真实变体**(部署位置/数据流/触发方式的真实差异),不是同一段话换模板置换。凑不出来的变体,一个实施例写扎实也远好于三个注水实施例。

实用新型注意事项:
- 以结构/连接/配合为核心,对照附图写。
- 写明形状、构造、位置关系(上/下/连接/嵌合),这是实用新型的保护重点。

## 摘要 → 完成标准:名称+领域+问题+方案要点+主要用途,无宣传语

细则第26条:写明名称、技术领域,反映要解决的技术问题、技术方案的要点、主要用途。**简短**(实务约300字内,2023版细则已删除300字法定上限——以简短为要,不以字数凑)。不得使用商业性宣传用语。有附图时在请求书中指定一幅作**摘要附图**(交给 patent-drawings)。

## 完成标准(交稿前)

- [ ] 五段齐全、有标题、顺序正确(细则第20条)
- [ ] 背景技术零虚构,三类素材只取其一
- [ ] 三呼应:问题↔背景缺陷、方案↔权利要求、效果↔数据或机理
- [ ] 支撑链:每条权利要求特征在说明书有出处
- [ ] 公开充分:缺参数/缺步骤/缺流程的段落已补
- [ ] 摘要含四要素要点,无宣传语
