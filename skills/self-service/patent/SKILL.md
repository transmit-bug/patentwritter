# Patent — 精简一站式（主链路：论文→交底书）

> 内容优先，格式可修。缺内容不可补，缺格式可后补。绝不编造专利号/论文/数据。

本技能是 `self-service` 精简整合版，单文件替代 `intake/drafting/drawings/compliance/exploration/filing` 六件套。主链路为 **论文→交底书**，技术论文直写交底书，综述类止步于可专利点分析。

## 何时用

- "这篇论文能写交底书吗" / "帮我把这篇论文改成交底书"
- "写个交底书 / 申请文件"
- 材料不限：论文、PPT、docx、口述、代码、产品资料；单份或多份

## 产物与目录

```
patents/<专利名>/
  drafts/
    application-info.md      # 四要素原文 + 关键参数 + 溯源一行
    技术交底书.md            # 主产物
    权利要求书.md / 说明书.md / 摘要.md  # 仅申请文件分支
    check-report.md          # 自检报告
    可专利点分析.md          # 仅综述分支
  figures/
    source/  embed/  preview/ # 原图/落版图/预览
  .patent/materials/         # 原文归档（能转就转，不能转留路径）
```

`<专利名>` 取标题核心词，确定后不再改名。`drafts/` 为可编辑定稿，`deliverables/` 仅按需导出 docx。

---

## 流程总览

```
摄入 → 读懂(分型) → 四要素 → 撰写 → 自检
         ├─ A技术论文 → 交底书
         └─ B综述/案例 → 可专利点分析（止步，不硬写）
```

每次最多 4 问，答完再追问；缺关键信息停在该步追问，不编造。

---

## Step 0 摄入

1. 原文原样落 `.patent/materials/`；`conversion` 能转 Markdown 就转，不能转保留路径手打要点，不阻塞。
2. 登记一行溯源到 `drafts/application-info.md`：`论文标题 / DOI / 来源路径`。正文仅附录 S 引用这一行，不贴检索过程。

---

## Step 1 读懂 — 论文分型（1轮）

用一页话术与用户对齐，不产大表：

- 论文解决了什么技术问题？现有做法怎么做的、有何缺陷？
- 核心手段一句话：输入是什么 → 做什么处理 → 输出给谁？
- 效果如何证明？（数据/机理）

据此分型：

- **A 技术论文**：有 `输入→处理→输出` 可复现链，有参数/公式/实施例其一 → 进 Step 2。
- **B 综述/案例/调研**：无可计算方法，只有研究方法综述或案例分析 → 产 `drafts/可专利点分析.md` 止步：

```markdown
# 可专利点分析
## 论文要点一句话
## 可专利化方向（1-3个）
1. 方向：把第X章的<全景拼接管线>提炼为"一种…方法"，输入/输出/效果
2. ...
## 下一步建议
选一个方向补充技术细节后进交底书，或换一篇技术论文
```

不把 B 硬拼成 8 章交底书。

---

## Step 2 问清 — 四要素（A类才进）

目标：拿齐 **技术问题 / 技术方案（最小可实施） / 区别特征 / 技术效果**，缺一不进撰写。按组顺序问，答过跳过，答案原文记入 `application-info.md`。

**A 技术问题**
1. 用在什么场景？做什么用的？
2. 没有它会遇到什么具体的技术麻烦？
3. 现有做法怎么做的？为什么不好？（为背景和区别特征准备）

**B 技术方案 — 能否让同行照做**
4. 总体怎么构成？输入输出边界与数据在模块间怎么流？
5. 分几步做？每步谁产生数据、做什么处理、传给谁？（3-8步，用自然段落，不要 `输入：/处理：/输出：` 三行填表）
6. 关键参数/阈值/取值范围与边界（空集、阈值相等、初始化）怎么处理？
7. 有核心公式或判断逻辑吗？写出式子并逐符号说明含义/量纲/范围与推导来源；无公式则说明如何用文字/流程保证可计算。
8. 硬件/部署形态？纯算法可写"复用通用服务器"。
9. 给一个完整实施例：参数取值 + 执行轨迹 + 输出结果。

**C 区别特征**
10. 相对现有做法改了哪一步、加了什么？删掉它问题还能解决吗？（能→非必要，放替代方案）
11. 有无等效替代？换载体/阈值还成立吗？

**D 技术效果 + 公开状态**
12. 好处是什么？有实测写明条件与数值，无数据写机理 `由于…因此…`，不编数。
13. 是否已公开（论文/展会/开源/销售）？何时何渠道？（仅记录）

**收口**：四项能否各用一句话说清？方案能否让同行复现？不能继续追问。

去学术化：`SLR/PRISMA/VOSviewer/三角验证` 等研究方法不进正文；`contribution` 列表改写为数据流段落；论文配图不整套搬运，至多复用1张架构原图。

---

## Step 3 撰写 — 交底书

单文件 `drafts/技术交底书.md`，推荐 7 节（够用即可，不卡标题白名单）：

```
# 一种<核心手段>的<对象+效果>方法/系统
一、技术领域
二、背景技术
三、要解决的技术问题
四、技术方案
  （一）总体架构
  （二）设计构思
  （三）分步实施描述
  （四）可复现性说明
  （五）关键算法/伪代码（可选，10-30行，标输入输出与关键行）
  （六）符号与参数说明
  （七）公式推导（可选，有式必有变量表+边界）
  （八）硬件组成与部署形态
  （九）具体实施例
五、技术效果
六、区别特征
七、替代方案
八、附图说明
附录 S — 溯源登记（仅一行 DOI/路径）
```

写法：
- 规范技术语言平铺直叙，段落说明 `谁产生—经什么处理—传给谁`，不填表。
- 公式与文字互指，不以流程图替代公式；图带 `图1 …` 题注，落 `figures/embed/` + `figures/source/`。
- 术语全文统一；背景只写三类来源（你已知的方案/领域公认问题/真实检索结果），无来源不写。
- 缺项不编 `N/A` 表，在 `application-info.md` 记 `待补充: X` 并追问。

**申请文件分支**（仅当用户要权利要求书/说明书时）：

顺序固定 **说明书 → 权利要求 → 摘要**。说明书五部分 `技术领域/背景技术/发明内容/附图说明/具体实施方式`，充分公开到同行能做出来。权利要求从说明书提炼：

- 删减测试：删掉该特征问题还能解决吗？能→非必要，放从权。
- 上位化三问（每抽象一层必过）：①仍解决原问题吗 ②说明书有实施例支撑吗 ③是否成纯功能限定（是则至少公开一种实现）。
- 独权：`一种<X>，包括：<共有特征>；其特征在于：<区别特征>。` 一段一句号。
- 从权兜底三方向：细化/变体/增强，按商业重要度排序。

---

## Step 4 附图

- 优先复用原文架构原图（拷至 `figures/source/` + `figures/embed/`）。
- 需新图且可用 dot 表达（流程/框图）→ 写 `figures/source/figN.dot`（`rankdir=LR`，≤8节点，横向饱满），`dot -Tpng` 出 `embed/figN.png` + `dot -Tsvg` 出 `preview/`；无 `dot` 则在 `drafts/check-report.md` 登记所需图，不阻塞撰写。
- 结构/剖视/电路等 dot 无法表达的图：登记待补充，不用框图冒充。实用新型的结构图为必备。

---

## Step 5 自检（轻量3项）

`drafts/check-report.md`：

| # | 检查 | 示例 |
|---|---|---|
| 1 | 支撑链：每条权利要求特征在说明书有出处（交底书分支查"区别特征是否在技术方案有对应"） | 区别特征在方案中无对应段落 |
| 2 | 清楚性：术语统一、权利要求单句号、无"优选/例如" | 同一部件混叫"传感器/感应器" |
| 3 | 一致性：标题/技术方案/效果/附图标记双向一致 | 附图标记20在文字未定义 |

有 `critical` 回 Step 3 修复后重检；无 `critical` 交付。

---

## 边界

- 发明可保护方法/产品/系统，实用新型仅保护产品形状构造；方法步骤作主特征时选发明。
- 外观设计为照片/图片，非 dot 图，另按六面视图准备。
- 递交与补正（电子系统操作、费用与期限）以官方系统为准，本技能止于自检后 `.md` 定稿。
